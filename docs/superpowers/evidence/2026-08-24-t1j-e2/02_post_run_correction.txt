B. CORRECTION: the opening-book condition was overstated
==============================================================
01_blocked.txt and the first draft of the card said initialMove() returns null
"only when moveNr > 5". That is wrong: the final expression can also yield null
for plies 0-5, when the chosen branch produces no move or one with x < 0.

What is actually true, and all the argument needs:
  moveNr > 5 GUARANTEES the opening book is bypassed, so setting moveNr >= 6 is
  a SUFFICIENT way to force the search path. It is not the only way null can
  arise.

Exact source, InitialMoves.java lines 55-74:
       public Move initialMove(final Match matchIn, int player)
       {
          match = matchIn;
          currentPlayer = player;
          Move retMove = null;

          if (match.getMoveNr() == 0)
          {
             retMove = firstMove();
          }
          else if (match.getMoveNr() <= 3) // simple answer with predefined moves
          {
             retMove = secondToFourthMove();
          }
          else if (match.getMoveNr() <= 5)
          {
             retMove = fifthOrMoreMove();
          }
          return (retMove != null && retMove.getX() >= 0) ? retMove : null;
       }

C. OMITTED LOAD-BEARING FACT: the engine-path classes are final
==============================================================
The argument "every relevant Match field is private, so same-package code
cannot set them" is incomplete on its own: a same-package SUBCLASS could
override getMoveNr() to return 6 and bypass the opening book without touching
any private field. That route is closed only because Match cannot be subclassed.

Exact declarations at the pinned revision:
    Match.java         24:public final class Match extends Observable implements Runnable
    Board.java         17:public final class Board
    FindMove.java      20:public final class FindMove
    InitialMoves.java  21:public final class InitialMoves
    GeneralSettings.java 14:public class GeneralSettings

  Match, Board, FindMove and InitialMoves are all `public final class`, so none
  can be subclassed. GeneralSettings is not final, but its constructor is
  private and its sole instance is a static final field created eagerly, so a
  subclass cannot be created or substituted either.

  => No subclass route exists anywhere on the engine path. The conclusion in
     01_blocked.txt stands, but for this reason in addition to field privacy.
