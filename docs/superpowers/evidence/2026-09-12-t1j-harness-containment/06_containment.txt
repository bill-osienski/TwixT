FOUR PROTECTIONS, AND WHAT EACH ONE BINDS
-----------------------------------------
1. A SECOND GATE CHECK AT THE PRODUCTION SEAM, before toolchain resolution,
   compilation, model loading or seed use — in H2's `play` and in H1's
   `setup`. Deleting one gate check now leaves the other.
2. AN ACT-AWARE CONTAINMENT BOUNDARY, `e4_screen_command.
   assert_production_acts_are_inert(what, acts)`, called at both seams
   immediately after the gate. In a process with `pytest`/`_pytest`/`unittest`
   loaded it refuses if ANY declared production act is still the genuine
   function — naming every one that is. The declared acts are the toolchain
   resolver, the compile step, the checkpoint load and the game loop (H1
   declares the first three; its setup plays nothing).
   🔑 THIS IS THE LINE BETWEEN A SEAM TEST AND A GATE-REMOVAL CONTROL, and it
   is structural, not a matter of intent: an honest seam test replaces every
   act, a control that deletes the gate leaves them all real.
   ⚠ MY FIRST VERSION OF THIS REPAIR WAS WRONG. It refused any test process
   outright at the top of the seam. That contained the incident and broke
   eleven honest tests with it — including the real-builder compatibility
   tests, which are the ones that caught the defect that VOIDed H2's first
   attempt. A containment check that cannot tell the two apart is an outage,
   and the full suite is what exposed it.
3. THE UNCONDITIONAL BOUNDARY AT THE MODEL LOAD stays, inside
   `_default_load_evaluator`: the last-ditch chokepoint every match path (L0,
   H1, H2, D1) shares. No test calls it for real.
4. THE HARNESS RESTORES RELIABLY AND REFUSES TO RUN ON IMPORT.
   * The gate-removal control is REMOVED, not re-aimed.
   * SIGTERM/SIGINT/SIGHUP handlers restore every injected source and exit 130.
   * Every restore is verified by hash; a mismatch prints "RESTORATION FAILED"
     and raises SystemExit(2) rather than running the next control against an
     unverified tree.
   * `if __name__ != "__main__": raise ImportError(...)`, above every statement
     that can touch a file — see incident 2, where reading the file ran it.

WHERE AUTHORIZATION IS RELAXED FOR A TEST, AND WHY THAT IS SAFE
---------------------------------------------------------------
Because the seam re-reads its gate, a seam test must open it. That happens in
exactly three places — H2's `seam_boundaries` fixture and H1's two
production-setup tests — and each one calls
`assert_production_acts_are_inert` FIRST, so the relaxation cannot coexist with
a real production act. Those places are the real-builder compatibility tests,
kept as required, and they are separated from the harness's gate-removal
controls by construction: the controls edit production source and leave the
acts real, which the boundary refuses.

THREE INHERITED H1 CONTROLS STILL REMOVE AN AUTHORIZATION CHECK
---------------------------------------------------------------
"the barriers move BELOW the plan load and the recorder", "the gate opens the
registration barrier too" and "registering the block opens the gate too" move
