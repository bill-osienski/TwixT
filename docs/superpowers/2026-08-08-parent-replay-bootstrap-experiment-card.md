# Parent-Replay Bootstrap — Experiment Card

**Date:** 2026-08-08 · **Status:** DRAFT, not countersigned · **Scope: one opt-in trainer
flag, one training run, one 400-game evaluation. Nothing else.**

Successor to the rejected cold-buffer continuation
(`docs/superpowers/2026-08-08-training-continuation-experiment-card.md`, result recorded at
`d376135`). That run changed **two** things at once — it began from an empty replay buffer
**and** dropped the parent's calibration objective — and lost by `−136` Elo. This card
changes **one** of them.

## Hypothesis

The regression was caused by the **cold replay buffer**, not by dropping the calibration
objective and not by continuation itself. Starting the buffer with parent-generated
experience should remove most of the collapse.

## Why this is a new mechanism, not a rescue

Do-not-repeat **#48** forbids rescuing the failed recipe with nearby endpoints, dose or
learning-rate changes, or more match games. The acceptable successor shape is named in the
rejection's own closeout section (`alphazero-value-search-experiment-ledger.md`, *Consequence
— reject this recipe, not all training*): a successor *"must name a genuinely different
mechanism and explain why it addresses this failure — for example, preservation of replay
state or parent behavior."* This is that. It changes
what the optimizer sees at step 1 and leaves dose, learning rate, endpoint, iteration
count and match size exactly as they were.

## Prediction, on record before the run

**Recovers much of the `−136` Elo collapse but still fails the promotion bar.**
Probability of a genuinely promotable gain: **10–20%**. That low prior is acceptable
because the test answers the most credible surviving question in under a day.

## The one code change

`--replay-warmup-games N`, **default `0`**.

When `N > 0`, before the iteration loop the trainer generates `N` self-play games with the
**loaded, unmodified** network and adds their positions to the in-memory buffer. No
optimizer step runs during warmup. Warmup games are ordinary self-play games on the
existing path — same workers, same MCTS and exploration config, same curriculum size, same
replay caps — so they are written to `--games-dir` like any others. That reuse is the point:
the change is a call site and a flag, not a subsystem.

Landing points, verified by reading them: the buffer is constructed at `trainer.py:2896`,
the iteration loop starts at `:3281`, and each iteration's training phase — inside which the
first optimizer step runs — is announced at `:4236`. Warmup belongs between `:2896` and
`:3281`. `ReplayBuffer` has **no save/load anywhere** —
confirmed by grep, not assumed.

**Explicitly not built:** buffer serialization or persistence, a replay format, migration
tooling, analyzers, telemetry frameworks, or any general replay-management surface.

**RNG continuity is pinned.** Warmup consumes the **existing master RNG stream**
(`master_rng`, `trainer.py:3065`) exactly as an ordinary self-play phase does, and iteration 0
continues from its **advanced** state. No reseed, no separate stream, no reset, and **no
intentional seed reuse**. This is not a guarantee of disjointness: per-game seeds are drawn as
random 31-bit integers, so ordinary collision risk between independently drawn seeds remains.

**Warmup fails closed on a short return.** If self-play reports fewer games than requested,
the run raises before the first optimizer step rather than training on a partial warmup.

### The four mechanical checks — and nothing else

1. **Default-off identity.** Omitted, and `--replay-warmup-games 0`, leave behaviour
   unchanged.
2. **Exactly `N`.** `N` warmup games, no more and no fewer, enter the buffer.
3. **No weight change during warmup.** Network parameters are identical before and after.
4. **Ordering.** The buffer is non-empty before the first optimizer step.

## Dose — state it precisely

> **500 warmup games generated by the unchanged parent, no optimizer step**, then the same
> frozen five iterations: **500 further self-play games and 800 training steps**
> (100 games / 160 steps per iteration at board size 24).

**Buffer sizing, measured not assumed.** The cold run produced **44,880 positions from 500
games** (~8,976 per 100). Warmup plus training is therefore ≈ **89,800 positions against
the pinned 100,000 cap** — roughly 10% headroom. `ReplayBuffer` is a **ring buffer: oldest
positions are overwritten when full** (`trainer.py:1793-1797`). `--buffer-size` stays at
`100000` deliberately, so the run keeps a single difference from the failed one. If the cap
is reached late, FIFO eviction drops the oldest — i.e. warmup — positions, which **weakens
the treatment rather than confounding it**. Record the final buffer size either way.

## Gate between the two runs

Evaluation starts **only** when `logs/eval/warm5_train.exit` contains `0`, the endpoint
exists, and its SHA-1 has been persisted by the gate below. A non-zero exit, a missing
endpoint, or a different filename means **stop** — not evaluate what was produced.

```bash
bash -c 'CK=checkpoints/alphazero-v2-warm5-from-calib020/model_iter_0005.safetensors
OUT=logs/eval/warm5_candidate_provenance.txt

[ -e "$OUT" ] && { echo "REFUSE: $OUT already exists"; exit 1; }
[ -f "$CK" ] || { echo "REFUSE: endpoint missing: $CK"; exit 1; }
[ "$(cat logs/eval/warm5_train.exit 2>/dev/null)" = "0" ] || { echo "REFUSE: training exit not 0"; exit 1; }
[ -z "$(git status --porcelain)" ] || { echo "REFUSE: worktree dirty"; exit 1; }

HEAD=$(git rev-parse HEAD) || { echo "REFUSE: git rev-parse failed"; exit 1; }
SHA=$(shasum -a 1 "$CK" | cut -d" " -f1) || { echo "REFUSE: hashing failed"; exit 1; }
[ ${#HEAD} -eq 40 ] || { echo "REFUSE: HEAD not 40 chars: [$HEAD]"; exit 1; }
[ ${#SHA} -eq 40 ] || { echo "REFUSE: sha1 not 40 chars: [$SHA]"; exit 1; }

printf "candidate: %s\nsha1: %s\ntrain_head: %s\nworktree_clean: true\n" \
  "$CK" "$SHA" "$HEAD" > "$OUT" || { echo "REFUSE: write failed"; exit 1; }
cat "$OUT"'
```

Every check precedes the write, so the artifact exists only if all of them passed. The
trainer records no git HEAD, so HEAD is captured here by hand. This gate ran as designed on
the cold experiment.

## Decision rule — the same bar, unchanged

**Success:** the candidate's overall **95% lower bound above 50%**. **Reject on convincing
one-colour harm:** a colour's own **95% upper bound below 50%**. As before, the per-colour
intervals need one **read-only** calculation, because `eval_summary._color_stats` emits no
interval:

```bash
.venv/bin/python -c "
import json
from scripts.GPU.alphazero.eval_elo import score_ci_trinomial
s = json.load(open('logs/eval/warm5_vs_calib020.json'))
for k in ('a_as_red','a_as_black'):
    d = s[k]
    lo, hi = score_ci_trinomial(d['wins'], d['caps'], d['losses'])
    print(f\"{k}: {d['wins']}-{d['losses']} caps={d['caps']} rate={d['score_rate']:.4f} \"
          f\"CI95 [{lo:.4f}, {hi:.4f}]  UPPER<0.50? {hi < 0.50}\")
"
```

## Frozen disposition — decided before the result

| outcome | disposition |
|---|---|
| **Bar not met** (lower bound not above `0.50`) | **Close ordinary continuation, including warm-buffer continuation.** No 250 or 1,000 warmup games, no ten iterations, no learning-rate or dose follow-up. |
| **Bar met** | **Replicate the entire training run once with fresh seeds** — new `--seed`, new evaluation interval, same recipe — *before* any investment in durable replay-buffer persistence. |
| **Clear loss** (materially below `0.50`, or colour harm fires) | **Close immediately.** |

The most likely outcome is the middle of the first row: **recovery without promotion** — an
interval straddling `0.50`. That is a real, informative result: it **supports the
parent-replay-bootstrap hypothesis**. It is not a causal attribution of the cold run's `−136`
Elo to the empty buffer — this run also carries a new training seed and 500 additional parent
games, so one run cannot isolate the buffer strictly. It **does not promote anything**, and it
is **not** a licence for a warmup-size grid.

## Deliberate omissions, and what they cost

- **No 64-game screen** — little stopping value in front of a cheap 400-game test.
- **No A/B/C/D.** Cost, stated: a strength-neutral result with a behavioural regression will
  not be visible here. The probes precede promotion; they do not gate this test.
- **No iterations 1–4 evaluation, no checkpoint sweep, no analyzer or telemetry framework,
  no learning-rate / dose / warmup-size grid.**
- **No external strength anchor.** It would improve the research programme but does not
  answer this mechanism question. It becomes worthwhile only if this test succeeds and
  continued training becomes an ongoing programme.

## Cost

smoke: the cold run's self-play took 1,289.7 s per 100 games (median of five measured

both measured on the cold run. Total ≈ **6 h 44 m**.

## A positive result is research evidence only

It does not promote a checkpoint. Safety probes precede promotion, and adoption is a
separate decision with its own record.
